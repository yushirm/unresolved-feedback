## Before you transmit

1. **Search existing issues** to see whether the signal is already logged.
2. **Keep one main topic per issue** so reports can be understood and tracked.
3. **Describe what happened and what you expected.** Reproduction steps are
   more useful than diagnosis guesses.
4. **Add only context you choose to make public.** A broad chapter, browser or
   device description is usually enough.

> [!CAUTION]
> This tracker is public. Do not post personal, confidential or sensitive
> information. Never post passwords, credentials, private save files or
> diagnostics. Check screenshots carefully before attaching them.

## Good signals look like this

| Helpful | Not needed |
| --- | --- |
| A short, specific title | Your real name or email address |
| What you did immediately beforehand | Account credentials or private URLs |
| What happened versus what you expected | A complete save or diagnostic file |
| How often it happens | Source-code or asset submissions |
| Optional browser/device and broad story location | Multiple unrelated problems in one issue |

## Tracker boundaries

- Public users may create and discuss Issues.
- Public users cannot push commits to this repository.
- `main` is locked, signed-commit protected and owner-governed.
- GitHub Actions, Wiki, Projects and Discussions are disabled.
- Pull requests are not a contribution route and will be closed without
  merging.
- Sensitive security information belongs in
  **Security → Report a vulnerability**, not in a public issue.

The detailed ground rules are in [CONTRIBUTING.md](CONTRIBUTING.md), with
private-report guidance in [SECURITY.md](SECURITY.md).
